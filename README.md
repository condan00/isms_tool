# isms_tool

KISA 주요정보통신기반시설 **Unix 서버 취약점 점검·조치·복구 도구** (ISMS 기준, 상/중 58개 항목).
Rocky Linux 9와 Ubuntu 24·26에서 검증했습니다. Rocky 10, CentOS 9·10, Ubuntu 20·22는 같은 계열이라 동작하도록 만들었지만 검증 전입니다.

## 하는 일
1. **점검**: 항목별 스크립트로 현재 상태를 양호/취약/수동 확인/해당없음으로 판정
2. **조치**: 자동(23)·승인 후 자동(26)·가이드 전용(9) 항목 중 선택해서 조치
3. **재점검**: 조치한 항목은 자동으로 다시 점검해 결과 확인
4. **저장**: 결과 리포트(JSON/TXT/Excel 등)와 미해결 항목 가이드 파일 생성
5. **복구**: 조치 직전 스냅샷으로 날짜별 복구 (CLI·GUI 공용)

## 구성
| 위치 | 설명 |
|---|---|
| `build.sh` | 터미널(CLI) 프로그램 빌드 → `isms_run` |
| `build-GUI.py` | GUI 프로그램 빌드 → `isms_run_gui` |
| `isms_lite_check.sh` | 파일 하나로 동작하는 점검 전용 스크립트(여러 서버 배포용, 시스템을 바꾸지 않음) |
| `code/` | 엔진(Python), TUI/GUI, 항목 스크립트(`scripts/`), 항목 정의(`data/items.json`), 테스트 |
| `tools/` | 스크립트·가이드 생성기, 시험용 취약 VM 시드 스크립트 |

사용법과 옵션은 [`README.txt`](README.txt)를 보세요.

## 빠른 시작
```bash
./build.sh                 # CLI 빌드
sudo ../isms_run           # 실행 (root 필요)

sudo bash isms_lite_check.sh   # 점검만, 취약 항목만 출력
```

## 주의
- `tools/make_test_vm_vulnerable_*.sh`는 **테스트 VM 전용**입니다. 운영 서버에서 실행하지 마세요.
- 조치는 시스템 설정을 바꿉니다. 반드시 시험 서버에서 먼저 확인하고, 조치 전 스냅샷으로 복구할 수 있습니다.
- 모든 58개 항목을 실제 VM에서 하나씩 검증한 것은 아닙니다. 검증 범위는 시험 환경에서 시드로 만든 취약 항목입니다.
